Agentical, the theory behind the runtime.

The guarantees are proved before they are shipped. This is the calculus underneath Pragmatic, stated with honest scope.

Pragmatic's guarantees are real because they are proved. Agentical is the probabilistic process calculus underneath the runtime: the reason crash recovery and faithful replay hold even when the model underneath is nondeterministic.

Durable execution is the proven substrate for reliable software: Temporal, Restate, Inngest, and DBOS all build on it. But its replay model assumes code is deterministic, so every engine works around LLMs by caching model outputs as opaque activities. Frontier models show only 50 to 96 percent determinism even at temperature 0. Pragmatic is durable execution built for nondeterminism from the ground up, holding durable replay, crash recovery, and information-flow reasoning together.

Model each LLM call as a probability distribution. Journal every realized outcome. Recovery becomes replay.

Two nondeterminisms are kept cleanly separate: probabilistic, resolved by the Oracle, and adversarial scheduling, resolved by a scheduler, the standard probabilistic-automata setup. The calculus itself is π-calculus-style, with a probabilistic small-step operational semantics in record and replay modes, over six primitives: Agent, Oracle, Channel, Memory, Journal, and Supervisor. A configuration is the 5-tuple <P;H;J;K;t>: agent pool, shared store, journal, channel state, and logical clock.

Three theorems, honest scope

T1, proved and mechanized in Lean 4

Replay soundness, the flagship result: replaying the recorded journal reproduces the original run's trace exactly, with probability 1, via a coupling on the shared oracle-randomness space.

T2, proved on paper

Probabilistic noninterference: secret inputs don't affect public observations, conditional on per-label oracle partitioning and a label-filtered scheduler.

T3, proved on paper

Compositional bounds: local per-agent probability contracts compose to a global union bound, with a Fréchet–Hoeffding fallback when independence fails.

From proof to running code

The Lean 4 mechanization covers T1's operational core, trace-equivalence, crash-resume, no-orphaned-effect, and cursor-determinism, all sorry-free. Channels, the measure-theoretic layer, and T2/T3 are not yet mechanized.

The Rust runtime is a zero-dependency reference implementation. Six integration tests demonstrate the three properties. Measured: 1000 of 1000 replay-determinism runs; ~230 ns constant-time journal append, flat to a million entries; and a ~1500× replay speedup under a latency-injected oracle, since replay performs zero model calls.

The Claude adapter extends the same guarantee to real tool-use agents. A wire test runs a full tool loop against a mock Messages API over live TCP sockets, kills the API mid-run, then shows that resume and replay reproduce the run bit for bit, with the tool having executed exactly once.
