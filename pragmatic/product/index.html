The product.

What ships today: a zero-dependency runtime, adapters for Claude and OpenAI-compatible models, a replay console, and bindings for six languages. All of it source-available on GitHub.

Get it

Clone it, run it.

Pragmatic is in public beta and the source is public. The core example runs without a model or an API key; the tool-loop example records a real Claude agent end to end, then resumes and replays it.

your terminal

# the source, on GitHub
git clone https://github.com/pragmaticco/pragmaticMain

# the runtime, no model and no key required
cargo run -p pragmatic --example research_agent

# a real Claude tool-use agent, durable end to end
ANTHROPIC_API_KEY=... cargo run -p pragmatic-anthropic --example tool_loop

# the same runtime from Python
pip install pragmatic-runtime

The repository carries the usage guide, the quickstart, and every example: github.com/pragmaticco/pragmaticMain.

The workspace

Seven crates, one runtime.

The core

pragmatic.

The runtime itself, sync and async: Journal, Oracle, Ctx, Runtime, Supervisor, capability checks, and information-flow memory. Zero dependencies. It links into the agent you already run; there is nothing to provision.

Program identity

pragmatic-macros.

One attribute, #[pragmatic::durable], gives a run its verified program identity. A journal recorded under one agent version refuses to replay under another, loudly and at the first step, instead of misreplaying quietly.

Model adapters

pragmatic-anthropic & pragmatic-openai.

Claude as a journaled Oracle, from plain completions to full Messages API tool-use loops. The OpenAI adapter speaks to any OpenAI-compatible server: OpenAI, Ollama, vLLM. Both are wire-tested over real sockets on every CI run.

The console

pragmatic-cli.

Five commands over your journal directory: runs, show, verify, export, serve. Verification walks the hash chain; export turns a run into a single HTML file you can attach to an incident ticket.

Python

pragmatic-python.

The same runtime, importable: pip install pragmatic-runtime. Journals written from Python are byte-compatible with Rust and with the CLI, so one console reads them all.

Everything else

pragmatic-ffi.

One C ABI behind stable C++, Java, Go, and Node bindings, carrying the full record, resume, and replay surface with typed faults. Implement the Oracle trait for any model client and the same guarantees follow.

The replay console

The journal, readable.

Every run, its chain status, and a full timeline: each prompt, model turn, effect intent and commit, and chain hash. Serve it live over your journal directory, or export one run as a self-contained HTML file that opens anywhere.

your terminal

# a live console over your journal directory
pragmatic serve --dir ./journals

# or the same timeline as one self-contained HTML file
pragmatic export research-42 --dir ./journals

Loopback-only by default. Journals contain prompts and outputs, and they are treated accordingly.

Measured, not promised
Seeded runs that replay byte-identically 1000 of 1000
Journal prefixes crash-tested for exact resume Every one
Tool executions across crash, resume, and replay Exactly one
Model calls during a replay Zero
Post-hoc journal edits that survive verification None

Every number above is a test in the repository. cargo test --release runs each claim on this page.

The terms

Source-available, not locked up.

Pragmatic is licensed under the Business Source License 1.1: read it, modify it, self-host it. Each released version converts to Apache 2.0 four years after release, so nothing stays closed forever.

Free while you build.

Free for non-production use, and for production use by organizations under one million dollars in annual revenue. Production beyond that takes a commercial license; the details live on the pricing page.

Scope, stated honestly.

Replay soundness is mechanized in Lean 4 and demonstrated empirically; the probability and information-flow theorems are pen-and-paper results whose disciplines the runtime implements. Journals are single-process on local disk today. The managed cloud backend is the commercial layer, and it changes operations, not semantics.
